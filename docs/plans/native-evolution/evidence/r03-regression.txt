Protocol/compatibility decisions
- Supported MCP version set is exactly {2024-11-05}. initialize returns that
  version for a supported request, and offers it as the supported fallback for
  a different version. The client must disconnect if the fallback is unusable.
- Standard path: initialize (version, object capabilities, clientInfo name and
  version), notifications/initialized, then tools. Repeated initialization is
  rejected. ping remains available during initialization. EOF closes stdio.
- Legacy compatibility: direct tools/list and tools/call before ANY initialize
  remain accepted. This is a deliberate legacy deviation from the standard
  initialization-first path, not a claim that such clients are fully compliant.
  Once initialize is accepted, tools are blocked with -32002 until initialized.
- Every request must carry jsonrpc="2.0", string method and string/integer id.
  Null, Boolean, fractional, array and object ids are rejected. Unknown envelope
  fields and invalid/unknown tool parameters are rejected before tool execution.
  The existing nonstandard fixtures without jsonrpc/full initialization need
  correction; the malformed-write behavior is intentionally not restored.
- Valid no-id messages never receive a response and cannot execute tools/call.
  Only notifications/initialized changes server protocol state. Unknown
  notifications, progress, cancelled and roots/list_changed are no-ops; this
  synchronous server has no outgoing or cancellable work to update.
- Batch arrays are not supported by this MCP endpoint and are rejected as
  invalid requests; successful/error responses remain single JSON objects.
- Parse/envelope/method/params failures are JSON-RPC errors. Missing memories,
  disabled exposure and invalid project_path execution failures are tool results
  with isError=true and text content, not JSON-RPC internal errors.
- Eight tool registrations drive schema listing, validation and typed dispatch;
  mnemosyne_codex_prep remains an alias of mnemosyne_prep_context. Integer limits
  are published and enforced: limit 0..10000, depth 0..100.
- Project selection and exposure remain per request. project_path is selection,
  not authentication or a sandbox boundary against a same-user local process.

Input/transport decisions
- Shared default maximum: 1 MiB. MNEMOSYNE_MAX_INPUT_BYTES may override it with a
  positive integer up to the hard maximum of 64 MiB. Invalid settings fail closed.
- CLI whole-input and MCP stdio frames use bounded reads. An oversized stdio
  frame (including no final newline) reports INPUT_TOO_LARGE on stderr and closes
  the connection without trying to parse or execute its tail. Invalid UTF-8 in a
  complete in-limit frame returns parse error -32700 and permits the next frame.
- SSE retains 64 sessions / 32 queued messages and the default 1 MiB body limit,
  with the same configurable bound. Oversize -> HTTP 413; bad UTF-8 -> HTTP 400.
- SSE binds only to localhost or literal loopback IPs. Non-loopback configuration
  is rejected until a separate authenticated deployment policy exists. Incoming
  Host and supplied Origin are restricted to the local listener authorities,
  including localhost:port and [::1]:port. Absent Origin supports native clients.
  A session id routes responses; it is not treated as authentication.
