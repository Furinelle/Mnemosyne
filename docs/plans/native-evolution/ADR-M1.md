# M1 source identity and schema boundary

R04 uses `store.json` with `schema_version: 2`, a random UUID `store_id`, and `min_writer_version: 2`. The writer number is a storage protocol version, independent of the Cargo package version. `store_id` identifies a copied store as the same logical store until an operator intentionally creates a new one; it is not an authentication credential. A path locates a store on this machine but is not durable identity. A v2 memory reference is `{store_id,memory_id}`. Bare IDs retain the v1 first-match lookup. V2 lookup rejects ambiguous unqualified IDs.

Upgrade is explicit. `preview_upgrade` reads only and reports whether a manifest is absent, current, or incompatible. `upgrade_store` takes the existing store lock and atomically publishes `store.json`; it does not rewrite legacy Markdown. A backup of the store before upgrade is the rollback source. V1 native writes inspect `min_writer_version` and refuse an upgraded store. An older binary without that check cannot be prevented from writing; stop those writers before upgrade.

`SourceEvent` identifies an underlying origin/session/event, independently of the agent retelling it. A `finding_key` distinguishes multiple findings from one event. The exact idempotency key is `(store_id, origin, source_session_id, source_event_id, finding_key)` and the payload hash is stored separately. A repeat with the same hash returns the original outcome; a changed hash returns `IDENTITY_CONFLICT`. `fact_key` optionally groups genuinely identical claims. A new event for a known fact appends a SUPPORT source record; the same origin event is counted only once. Evidence count is a ledger size, never a claim of statistical independence.

SUPPORT checks current working Markdown under the store lock before appending: its body must match the original fact and its status must remain active, unexpired, and not invalidated. Corrections, replacements, and archived records require a new fact key or explicit reconciliation. The retelling agent name is excluded from payload identity; content, attribution kind, requested verification state, redacted summary, expiry, importance, title, and tags are included. V2 requests reject unknown fields and types outside the store's configured `memory.types`.

Markdown stays readable. V2 adds only flat frontmatter fields (`recorded_at`, `source_event_id`, `source_session_id`, `source_kind`, `verification_state`, optional `fact_key`). The versioned `evidence/<id>.json` sidecar is canonical provenance/identity data and contains enough of the original memory to repair an interrupted first publication. The sidecar is atomically written before Markdown under the store lock; interrupted publication is repaired before the next v2 write/read. Updating SUPPORT touches only the sidecar. SQLite and `MEMORY.md` are derived indexes. No raw transcript is retained, only source identifiers, hash, and optional redacted summary.

`source_kind` is content origin, not verification. Callers may request `unverified` or `evidence_attached`; a request claiming `verified` is downgraded to `unverified`. Only a future trusted verification operation may assign `verified`. Missing legacy source is `unknown`, not `user_asserted`. `recorded_at` is injected RFC3339 UTC; the old date-only `created` is left as a date.
