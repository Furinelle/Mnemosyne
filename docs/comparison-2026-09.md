# 2026-09 记忆系统对比与改进

2026-09-12 核对下列官方仓库和文档。对比针对本地 Markdown、中文技术检索、多个代理共享，以及运维事实需要来源和时效的使用方式。没有运行竞品性能基准，以下是架构与功能取舍。

| 项目 | 可借鉴的设计 | Mnemosyne 的取舍 |
|---|---|---|
| [Mem0](https://github.com/mem0ai/mem0) | 多信号检索、持续追加事实、时间推理 | 保留已有混合检索，先修真实中文查询；不把 LLM 写入或云服务设为前提。其平台分数不能替代本地评测。 |
| [Letta / MemFS](https://github.com/letta-ai/letta-docs-md/blob/main/concepts/memfs/index.md) | Markdown 文件记忆、部分核心文件常驻、其余按需读取 | 继续使用 core + working + show；严格控制每次注入的实际预算。 |
| [Graphiti](https://github.com/getzep/graphiti) | 事实有效时间窗、来源 episode、保留历史 | 复用 expires / supersedes / evidence，补齐检索端过滤和结果元数据；无需引入图数据库。 |
| [Basic Memory](https://github.com/basicmachines-co/basic-memory) | 本地 Markdown + SQLite、项目隔离、MCP 接口 | 与现有底层最接近。复用已有 MCP 行为标注，统一 CLI/MCP 返回字段，避免各入口逐渐分歧。 |
| [claude-mem](https://github.com/thedotmack/claude-mem) | 紧凑索引后按需取详情、来源 ID、上下文成本可见 | 保留摘要 → show 路径，修正被预算裁掉的记忆仍被标为已读的问题；不增加常驻 worker 或默认全量采集。 |

## 本次落地

1. **检索更贴近中文技术请求。** 原先按前八个 bigram 提取关键词，长中文前缀会挤掉后面的项目名。现在以完整文字片段提取，再由检索层分词；回归用例覆盖请求后半句的项目关键词。
2. **多代理注入可靠。** 只记录真正输出的 ID 并增加访问次数，文件标题与中文截断都计入预算；session 状态加锁、读取时检查 TTL，避免并发覆盖和过期状态继续抑制召回。重复提问但没有实际注入时，不再虚增记忆强度。
3. **时效与来源可判断。** 过期记忆不再等维护任务才退出默认检索，候选截断前过滤，图扩展也不能经由过期记录召回其它条目；过期副本不会拦住刷新写入。显式历史查询仍可回看。搜索带来源、记录日期、有效状态、替代者和证据引用。
4. **自动写入保留消息边界。** Codex 内部推理与工具收件消息不进入抽取；结构化 transcript 不再转成容易伪造角色的纯文本后重解析。LLM 配置或响应失败不推进游标，防止恢复后永久漏记。

保留 Python + portalocker、Markdown 原文件、SQLite 派生索引和现有代理入口。索引新增过期元数据并自动迁移，记忆文件无需迁移。

## 使用边界

`created` 表示记录日期，`source` 表示记录代理；它们都不代表事实已被重新验证。已有但没有到期日或 supersedes 关系的旧事实不会仅凭年龄自动判错。VPS 地址、部署版本、服务状态仍需按任务核查；用短 `evidence` 引用保留可追踪的报告或文件位置。

启发式蒸馏继续保守提取，并不保证记下所有会话成果。它不是完整任务日志，也不能自动判断每条结论是否真实。已知、明确的重要发现仍可用 `write` / `ingest` 保存；不要保存凭据或原始敏感会话。

验证使用合成中文技术数据，覆盖预算、消息角色、来源、失效事实和并发；保留现有完整测试和检索回归门槛。未以对比研究为由启用远程模型、重写现有记忆或调整用户宿主设置。
