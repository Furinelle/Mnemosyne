# Mnemosyne 0.6.1 Audit Fixes Implementation Plan

> **For Codex:** Execute this plan task-by-task with strict red-green-refactor discipline. Do not weaken regression assertions to make a test pass.

**Goal:** Fix the nine confirmed correctness and release-integrity defects from the 2026-07-18 audit without changing Mnemosyne's public memory format or broadening the feature set.

**Architecture:** Put read-modify-write operations behind small store-level transaction helpers, route every finding source through one classification/write path, and enforce policy at the final retrieval/MCP boundaries. Prefer conservative behavior when legacy metadata cannot be merged losslessly. Keep the patch release-compatible and verify both the Python package and plugin metadata from one version source.

**Tech Stack:** Python 3.11+, pathlib, portalocker, SQLite FTS5/WAL, pytest, Hatchling, MCP Python SDK.

## Task 1: Make memory access updates and maintenance scheduling atomic

**Files:**
- Modify: `mnemosyne/store.py`
- Modify: `mnemosyne/cli.py`
- Modify: `mnemosyne/hooks/_common.py`
- Modify: `mnemosyne/hooks/session_start.py`
- Test: `tests/test_concurrency_v2.py`

### Step 1: Write failing concurrency regressions

Add a process-level regression proving that an access bump racing with `link --rel supersedes` preserves the newer `status`, `invalidated_by`, and link metadata. Add a second regression proving that simultaneous SessionStart hooks can spawn at most one maintenance process for a due store.

Run:

```bash
uv run --no-project --with pytest --with-editable . python -m pytest tests/test_concurrency_v2.py -q
```

Expected: the new tests fail against the current stale read/write and marker check/spawn/mark sequences.

### Step 2: Introduce narrow store transaction helpers

In `mnemosyne/store.py`, add a deterministic multi-store lock context manager that deduplicates and sorts roots before acquiring `.lock` files. Add an access-bump helper that acquires the target store lock, rereads the current file, changes only `access_count`, `last_accessed`, and the bounded strength bonus, then atomically writes the current object back.

Update CLI and hook search writebacks to call this helper instead of persisting an object loaded before the race. Wrap relationship mutations that touch multiple stores in the sorted multi-store lock and reread their endpoints after lock acquisition.

### Step 3: Serialize the maintenance due check

In `mnemosyne/hooks/session_start.py`, hold a dedicated marker lock across the due check, successful child spawn, and marker update. A contending hook should skip rather than block. Do not advance the marker when process creation fails.

### Step 4: Verify and commit

Run the new concurrency tests three times, then the existing concurrency and hook tests.

```bash

Assert that no metadata or graph edge is lost and the backlink is rewritten to the survivor. Add a conflict case whose status or expiry cannot be reconciled; assert that consolidation skips it rather than deleting data.

### Step 2: Implement a conservative lossless merge

Make `merge_memory` produce a candidate survivor that unions tags and links, preserves evidence and provenance, combines access counters deterministically, and retains the most recent access time. Reject merges with incompatible lifecycle fields or unknown conflicting metadata.
